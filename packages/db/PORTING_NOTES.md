# Porting notes: Postgres to D1 (ODY-296, lot L1)

State after L1: `packages/db` is sqlite-only (`sqliteTable`, `drizzle-orm/d1`), `tsc --noEmit` is green for
this package alone, and the single baseline `drizzle-d1/0000_baseline.sql` creates 104 tables (103 + `trigger_flag`) and 160 indexes on a
local D1. Nothing outside `packages/db` was touched except the `auth:generate` script of `packages/auth`.

## Table count

103 `pgTable` before = 85 (`app.ts`) + 4 (`scim.ts`) + 14 (`auth.ts`) = 103 `sqliteTable`, plus `trigger_flag` (L1 review follow-up) = 104.
The S3 spike showed 90 because it converted only `app.ts` and `scim.ts` (89) and kept a one-table stub of
`user`; the 13 other better-auth tables (session, account, verification, passkey, apikey, jwks, oauth_*) were
missing. `auth.ts` is now generated by the better-auth CLI (`bun run auth:generate`, config in `auth.cli.ts`,
which mirrors the plugins and the `role`/`active` user fields of `packages/auth/src/index.ts`).

## Schema constructs: carried over by the codemod and verified to apply on D1

| Postgres | SQLite | Consequence for code |
| --- | --- | --- |
| `timestamp` | `integer({ mode: 'timestamp_ms' })` | still `Date` in TS; raw `sql` comparisons see epoch ms |
| `date` (start_date, due_date, spent_on, value_date...) | `text` ISO `YYYY-MM-DD` | same strings as before; lexicographic order = date order |
| `jsonb` (34 cols) | `text({ mode: 'json' })` | no `->>`, `@>`, `jsonb_*` operators: use `json_extract` |
| `serial` / `bigserial` (`agent_chat_event.id`) | `integer primary key autoincrement` | |
| `boolean` | `integer({ mode: 'boolean' })` | raw `sql` must compare to 0/1 |
| `uuid ... defaultRandom()` (token, public_id x5, epoch, document_comment.id) | `text` with `$defaultFn(crypto.randomUUID)` | the default lives in the ORM, not in SQL: a raw INSERT (L8 data migration, scripts) must supply the value |
| `bigint({mode:'number'})` (size_bytes x4, revision.rev) | `integer` | safe up to 2^53, same as before |
| `doublePrecision` | `real` | |
| `numeric` (`issue.estimate_points`, `custom_field_value.value_number`) | `real` | type changes from string to number; exact decimals are lost |
| `CHECK` (50 in app.ts, 1 in scim.ts) | `CHECK`, unchanged | valid in SQLite; re-check on real data in L8 |
| partial `UNIQUE`/`INDEX ... WHERE` (17 + 2) | same | valid in SQLite; `WHERE` accepts deterministic expressions only |
| expression indexes `lower(...)`, `lower(trim(...))`, `CASE` for least/greatest | same | `ai_agent_team_username_uq`, `issue_project_title_idx`, the `issue_link` pair index |

`defaultNow()` became `(CAST(unixepoch('subsecond') * 1000 AS INTEGER))`; `$onUpdate(() => new Date())` is
ORM-side, as before.

## Postgres constructs not covered by the codemod

1. **Triggers: ported** to `drizzle-d1/0001_triggers.sql` (30 pg triggers, 20 functions -> 81 SQLite
   triggers, one per operation, bumps inlined; header of the file lists every deviation). Hand-written,
   so drizzle-kit never touches them but a table rebuild drops them; `triggers.test.ts` counts them.
   `set_config('app.document_rebalance' | 'app.document_checkpoint')` in `apps/api/.../documents/service.ts`
   (lines ~1071 and ~1580) must become a `trigger_flag` row inserted/deleted inside the same `db.batch`
   (HORS PERIMETRE for L1, owned by the documents lot).
2. **Seed data**: `drizzle-d1/0002_seed.sql` inserts the `storage` app_setting (INSERT OR IGNORE). Nothing
   else needs seeding: the default team role is created with the team (`teams/service.ts`), `model_price`
   rows are per-workspace overrides with no literal data in the legacy migrations, and `migration.teams`,
   `migration_count` and the permission backfills are history for the L8 data-migration script.
3. **`db.transaction(...)` does not exist on D1** (drizzle throws): 83 call sites in 40 files of `apps/**` and
   `packages/**`. Use `db.batch([...])` (atomic) when the statements are known up front, otherwise one
   statement (`INSERT ... SELECT`, `UPDATE ... RETURNING`). `createWorkspace` shows the pattern
   (`last_insert_rowid()` inside a batch).
4. **Locks**: 20 uses of advisory locks (`pg_advisory_xact_lock`, e.g. the attachment quota) and 28 of
   `FOR UPDATE`. D1 has no equivalent; `lockAttachmentStorage` was removed from `packages/db`; use
   `reserveStorage(db, ...)` (INSERT ... SELECT ... WHERE used + size <= quota, one statement).
5. **Raw SQL** outside `packages/db`: 205 `now()`, 63 `.execute(sql...)`, 40 `ilike`/`ILIKE`. SQLite has no
   `now()` (pass a `Date`, or use `unixepoch('subsecond')*1000`), no `ILIKE` (`LIKE` is case-insensitive for
   ASCII only), no `::cast`, `to_char`, `date_trunc`, `extract` (analytics module). Every `sql` fragment in a
   `.where()` there needs the same review.
6. **D1 limits the Postgres code never met**: at most 100 bound parameters per statement (bulk
   `.values([...])`, `inArray(ids)` with many ids, the Plane/Linear import), 2 MB per row (`project_document`
   content, `note_board` canvas, `agent_run` traces), 10 GB per database, foreign keys always enforced (a
   migration that rebuilds a table needs `PRAGMA defer_foreign_keys = on`).
7. **Removed Postgres tooling**: `backup.ts` (+ its test, `pg_dump`, `BACKUP_*`), `wait-for-migrations.ts`,
   the advisory lock and postgres-js retry loop of `migrate.ts`, and `BUILD_MIGRATIONS_DIR` (a build's own
   tables, applied after the core's). `migrate.ts` is now a Node helper for tests and scripts
   (`migrateD1(db)`); deployed databases use `wrangler d1 migrations apply`, and D1 Time Travel replaces the
   pre-migration dump. A build-specific migrations folder needs a new design.
8. **Still pointing at the Postgres flow** (not touched here, for the deployment lots): `package.json`
   (`db:migrate`, `db:migrate:test`), `turbo.json`, `scripts/setup.ts`, `docker-compose*.yml` (`migrate`
   service), `charts/itsaplan` (init containers, configmap), `apps/api/Dockerfile`, `.env.example`
   (`DATABASE_URL`), `docs/self-hosting.md`, `docs/development.md`, `docs/dev/revision-engine.md`, root,
   `apps/api` and `packages/auth` AGENTS.md, `.agents/skills/security-audit`.
9. `packages/auth` can add tables through `readAuthExtensions()` (`extensions.schema`); `auth.cli.ts` does not
   include them. `packages/auth`'s `auth:generate` now delegates to `packages/db`.
10. `@repo/crypto` (used by `secrets.ts`, `notification-settings.ts`) relies on `node:crypto`: Workers need
    `nodejs_compat`.

## API changes inside `@repo/db` (every caller breaks, by design)

- `db` is gone. `createDb(env.DB)` returns a `Db`; `DbExecutor` is an alias of `Db` (no transaction type).
- `getSetting`, `getOrCreateSetting`, `setSetting`, `readSecret`, `writeSecret`, `getInstanceEmailConfig`,
  `hasConfiguredEmailProvider`, `getProjectEmailConfig`, `getInstanceBotConfig`, `readNotificationConfig`,
  `getDeliveryConfig`, `getStorageSettings` take `db` as first argument.
- `projectStoredBytes`, `projectTeamId`, `workspaceStoredBytes` take `executor` first, with no default.
- `lockAttachmentStorage` is removed.
